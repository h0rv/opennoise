OpenNoise · verified local FMA slice · 15 October 2026

A music explorer built offline,
served as ordinary files.

Python prepares the data, numerical model and map. Your browser searches those prepared files and plays excerpts. The historical local bundle is not publicly cleared; a separate minimized candidate excludes conflicting and absent embedded license declarations. There is no live AI service, database server, Worker or WASM required to use this version.

From source records to listening

FMA metadata + numeric features → verified native IDs → offline model, neighbors and coordinates → static JSON + HTML + JavaScript
Reviewed MP3 excerpts → verified collection manifests → browser playback
01 · Source

A large catalog, a small audio sample

109,727 tracks · 16,916 artists · 164 genres in the retained Free Music Archive metadata. Numeric features cover 106,574 tracks.

Historical local listening contains 133 distinct recordings from 129 artists, covering 143 source genre labels. Its receipts established byte custody and source metadata, not public license clearance. These are about 30-second excerpts, not the full audio catalog.

02 · Ingestion

Keep the source identity

Bounded official archive ranges preserve native track, artist and album IDs. ZIP members, sizes, CRCs, SHA-256 hashes, source receipts and license fields are checked. Every retained MP3 is decoded completely. Decoding and source hashes do not resolve conflicting embedded license declarations.

Partial archive capture does not verify the whole archive checksum. No name-based cross-dataset identity bridge is invented.

03 · Features and model

44 audio summary numbers per track

FMA-authored Librosa means: 20 MFCC, 12 chroma, 7 spectral contrast, and 5 energy/spectral/zero-crossing measures. They are existing descriptors, not a neural embedding or an LLM judgment.

A positive-only diagonal Gaussian scores each supported genre, with training prevalence as a prior. It learns from source track labels; it does not turn guesses into artist genre facts.

04 · Discovery

Source tags and suggestions stay distinct

Genre pages use direct FMA track tags. Up to three starting excerpts use distinct artists, fewer direct tags, then native ID. This is a deterministic browsing heuristic.

Suggested excerpts are nearest neighbors in standardized 44-dimensional feature space, within each attached collection. Artist, album and exact-feature components are excluded; at most six distinct-component neighbors are returned.

05 · Map

Two mathematical axes

PCA fits the standardized descriptors of 92,270 finite training rows. Genres use supported training-positive centroids; artist display positions average their finite associated tracks.

158 genres and 16,109 artists have coordinates. Missing positions stay missing. PC1 and PC2 are not named musical dimensions; proximity is not a validated recommendation.

06 · Browser

One player, explicit Play

Plain JavaScript loads local JSON lazily. Native IDs select the right original, expanded or coverage audio manifest. Credit and license links accompany playback.

Root navigation keeps the player; reload is silent. Full catalog document links leave the root player. The root-map integration reuses the same coordinates and collection audio.

Training and evaluation, exactly

Components join native artist IDs through shared albums and exact duplicate feature vectors. A deterministic component hash assigns nominal 80/10/10 train/validation/test buckets; realized counts are 94,953 / 7,332 / 6,468 tracks. Another 974 tracks with unresolved artists are excluded from these folds. The largest component has 39,750 tracks, so proportions are uneven. This isolation does not resolve unknown performer aliases or all near-duplicate recordings.

Normalization uses only complete finite training rows. Label variances are shrunk halfway toward global variance, floored at 0.1 in standardized units; labels need five training positives. Queries with missing active features or any absolute standardized value above 12 abstain. There was no validation-based parameter selection. These outer folds had been inspected in earlier work, so the reconstruction results are diagnostic rather than a fresh blind confirmation. The model supports 158 labels.

Test observed-label Recall@10 is 39.59%, versus 36.63% for training-label popularity. Test first-positive MRR is 0.313, below popularity's 0.319. These measure recovery of incomplete source annotations, not listening quality. The 88-feature mean-plus-standard-deviation experiment worsened Recall@10 to 33.23% and was not adopted.

A fixed-ranking component diagnostic puts the test Recall@10 gain at 2.96 percentage points, with a paired component-bootstrap 95% interval of −1.29 to +6.55 points, spanning zero. Equal weighting of components leaves acoustic and popularity recall nearly tied. These conditional, fixed-model results use previously inspected annotation data; they are not fresh confirmation or evidence of musical relevance.

A separate fixed-model loss audit found no missing-feature rows among the 263 rare-label test positives: 13 top-ten hits, 236 scored active-label misses and 14 inactive-label positives. Repairing only heldout missing descriptors cannot improve rare-label test recall; even its optimistic overall test ceiling is 42.02%, versus 39.59% currently. This does not estimate gains from retraining, repairing training inputs or acquiring independent examples.

Neighbors reuse the frozen training normalization and squared Euclidean distances, with native ID tie-breaking. They do not use the Gaussian genre scores or search all 133 recordings together. Independent scalar replay checks exported rankings.

What is still weak

Musical relevance and representativeness remain unmeasured. Browser tests prove controls work; numerical replay proves calculations agree. Neither proves a person will find the music similar or a genre example representative. Blank listening questionnaires are not results.

  • 133 recordings are only about 0.12% of catalog tracks. Many genres have few examples; the historical metadata-allowlist slice left 21 silent labels: 19 lacked a metadata-allowlist candidate and two had no native tracks. That was not a public-clearance result. The new 55-recording candidate leaves 71 of the 164 source labels without playback.
  • FMA genre vocabulary and sampling do not reproduce Every Noise's breadth. A playable label is not broad coverage of a musical tradition.
  • Source labels are incomplete. An absent label is unknown, not a verified negative. Scores are not calibrated probabilities.
  • MusicBrainz and other historical research inputs exist separately; they are not automatically merged into the current FMA audio model. A separately approved ccMixter pilot stopped at its first anonymous API request: the execution proxy denied CONNECT with 403. No ccMixter metadata or audio was acquired; no retry or bypass was attempted.

A separate conservative candidate

The embedded-tag audit found 59 recordings whose supplied license URLs conflict with the metadata and 19 without an embedded CC declaration. Both groups are excluded. A separate candidate selects 55 matching-declaration recordings from 53 artists, covering 93 native genre labels, with 53,715,457 audio bytes. Matching declarations are source evidence, not a warranty of uploader authority.

The candidate gate rechecks actual embedded tags, requires reviewed source and embedded credits, preserves original MP3 bytes, and projects only named attribution and native identity fields. Contact/payment fields, biographies, comments and lyric text are not copied into its JSON. Some original MP3s retain embedded extra text; that is disclosed rather than silently stripped. Missing native URLs remain unknown, with separately labeled supplied embedded URLs where available. Historical receipts and assets are unchanged. Source-evidence eligibility does not itself authorize upload or deployment. This new candidate offers genre-first names and subset counts, searchable genre/artist/track directories, native-ID deep links, browser history and a player that survives navigation; it does not include the historical explorer’s map or model-neighbor interface described above.

A distinct minimized model-input derivative contains numerical descriptors, native IDs, observed memberships, frozen weights and saved ranks: 23,387,073 payload bytes, with a 23,418,880-byte archive. It contains no performer names, track titles, contact fields, raw metadata or audio; dataset-author attribution is retained. Independent replay recovered all 13,800 heldout query metrics. It supports fixed-output verification; it is not the complete raw capture needed to rerun the existing native extraction/fitting pipeline.

Static hosting is enough; artifact custody is the missing step

Current GitHub CI runs source checks on pushes and pull requests. It does not deploy. It installs locked dependencies and runs formatting, lint, type, JavaScript and Python checks. Optional real-data contracts run separately against the workspace export. The existing poe deploy path builds a separately certified public dist; it must not be pointed at this local research export without an explicit reviewed promotion.

Chosen persistence route: the user approved GitHub release assets for the reviewed derivatives. A supported binary-upload path is not currently available, so publication remains technically pending. A pinned release asset can supply CI with a known hash while keeping datasets out of Git. Do not make every code push re-download mutable third-party audio or silently substitute newly fetched data.

  1. Freeze the exact public output, included licenses/credits and source commit.
  2. Make the immutable artifact accessible to CI and verify its SHA-256 plus closed file inventory.
  3. Run source checks and browser checks against that artifact.
  4. Only then enable a narrowly scoped main-branch static deployment. Keep raw feature captures and model training offline.

A typical excerpt is roughly 1 MB. One thousand visitors playing ten excerpts transfer roughly 10 GB of audio, before caching and catalog traffic. Nobody needs to download the whole 240 MB site to view one page.

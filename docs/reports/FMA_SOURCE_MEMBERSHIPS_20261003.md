# Component calibration of overlapping native FMA source memberships

This experiment implements a missing engineering layer: bounded overlapping source-conditioned suggestions with explicit calibration support, abstention, rank sensitivity and independently reconstructible outputs. It **does not satisfy musical membership calibration or Every Noise granularity**. The fixed arm provides negative evidence about the available native calibration coverage rather than manufacturing a pass.

The original FMA Gaussian, training-only normalization, all original source files and frozen artist/album/exact-full-feature duplicate components remain unchanged. No fit or model selection occurred. Before this arm ran, a separate declaration froze target source-positive coverage 0.8, at least 20 positive calibration components per label, maximum 20 suggestions, rank sensitivity radius 2 and 200 deterministic component-bootstrap draws. Declaration SHA256: `39017287328e88c26ef23789cb35ed22eb4f250e5a61ae767a2fd84b9f01ccdb`.

Validation components are partitioned solely by SHA256 of the new revision and exact component ID: one half calibrates thresholds, the other confirms the new arm. The old aggregate validation baseline had already been reported; this is a newly partitioned arm confirmation, not a claim that the historical dataset was unseen. The old test is reported only as a previously observed diagnostic. No result was used to change support, threshold, cap, arm or split.

For each observed positive label, calibration retains the **worst rank among all positive tracks in each component**. An abstained/missing feature row contributes vocabulary size + 1, never disappears. The threshold is the ceil((n+1)×0.8)-th positive component order statistic. Fewer than 20 components or an impossible threshold abstains for that label. Source-label absences are unknown; no negatives, classifier precision or calibrated posterior probabilities are inferred. A query can have multiple memberships. Passing labels are ordered by rank/threshold and capped at 20. The component-positive percentile is a descriptive tail fraction, explicitly not a probability that music belongs to a genre.

Only **11/164 labels** have thresholds; **152 labels lack 20 independent positive calibration components**, and one has an unsupported missing-score tail. Confirmation rare-source positives recover **0/191**; test rare positives recover **0/249**, with below-five-support positives **0/14**. No unseen-positive test examples exist, so there is no empirical unseen-label result. The 45/34/99 unlabelled queries remain counted. Missing descriptor queries and unsupported-range queries remain in source-positive recovery denominators.

Confirmation raw acoustic Recall@20 is 50.91%, compared with this restricted source membership arm's 41.02%. This is not an improved ranking claim. The new arm exposes the efficiency/support cost of source calibration: maximum output is eleven here because only eleven labels are available. It cannot create validated rare or microgenre memberships from absent evidence. Per-label fully recovered positive-component counts are saved; confirmation coverage ranges from 61.90% to 100% among the eleven labels, so even nominal 80% is not established uniformly. No exchangeable-component or stationary-domain assumption is claimed. Bootstrap intervals describe component resampling uncertainty, not licensing, source completeness or musical truth.

Rank stability is separately recorded for crossing the threshold and for competition at the bounded set boundary under ±2 rank perturbations. This is algebraic sensitivity, not acoustic/audio robustness or independent musical judgment. Confirmation stable-positive recall is 40.78%; test diagnostic is 36.77%.

The preserved local pack `data/examples/fma-source-memberships` includes all 13,800 original validation/test queries, thresholds, declaration, implementation snapshot and per-file hashes. Its public lossless representation is `data/recipes/fma-source-memberships-v1`; follow that README to materialize the nine exact files into a new directory. The binary original remains in private recovery storage. `scripts/replay_fma_memberships.py` replays every threshold, suggestion and metric, including self-rehashed-threshold forgery rejection. Nine targeted tests plus Ruff and type checks passed for the model; four additional recipe guards and an exact nine-file round trip passed before publication. Independent native source custody comes from the prior full FMA source/model audit; saved-rank replay does not claim to reconstruct absent native CSVs.

Next evidence genuinely required: more licensed native positive evidence with enough independent components for rare labels; an exact artist/recording identity bridge before cross-source merges; independent listener judgments before interpreting source-recovery scores as musical membership; and a fresh external confirmation set before selecting or promoting subsequent models. The model namespace stays `fma-track-source-model-v1`; no FMA artist or MusicBrainz genre claims are fabricated, and no experimental deployment occurs.

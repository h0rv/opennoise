About OpenNoise

How the atlas is built

OpenNoise builds a genre map and similar-artist graph from ListenBrainz listening counts, AcousticBrainz audio descriptors, and genre labels from several sources.

The reference is Glenn McDonald’s Every Noise at Once. Its genre map uses Spotify data through 19 November 2023. After his December 2023 layoff, McDonald lost the internal data access needed to keep much of it current. The map remains a snapshot; some public research tools are still maintained. See his status notes.

OpenNoise uses Every Noise genre names and artist memberships as training data. It is not an independent rediscovery of those genres. Dependence and history →

01

Architecture

Models run offline in Python. The website reads their exported catalog; it does not train a model or fetch Every Noise data when you open it.

02

Models

Listening graph
Start with a sparse listener × artist count matrix. Log counts and inverse-frequency weights reduce the influence of listeners with very broad histories. Cosine similarity keeps 50 neighbours per artist. A separate implicit ALS model supplies 128-dimensional listening vectors for layout. Graph code · ALS settings
Membership & discovery
Known artist–genre examples seed a row-normalized listening graph. Propagation gives artists weighted genre memberships. Leiden clustering on the listening graph finds additional groups at resolutions 256, 1,024 and 4,096; these are not a strict nested tree. Genre code · Clustering settings
Naming & enrichment
Discogs styles and Wikidata genres name clusters using support, rarity and lift against their context. A separate micro-genre model combines places and styles, scores artist membership, then ranks proposed names using models trained on visible Every Noise genres. Discogs styles also rerank existing similar-artist candidates; that rerank does not rebuild the genre graph. Cluster naming · Micro-genres · Rerank settings
Map & Islands
Aggregate artist ALS and AcousticBrainz vectors by genre membership, then normalize. Map uses cosine UMAP, rotates its output toward audio descriptors and rank-spreads both axes. Islands fits a separate spectral-initialized UMAP to the same kind of vectors. Related genres are the ten closest by high-dimensional cosine similarity, not screen position. Missing audio-axis values can be estimated from listening neighbours. Layout code · Map transform · Settings
Export & browser
Export memberships, names, stable IDs, coordinates and neighbours into a versioned JSON catalog. GitHub Pages deploys that prebuilt catalog with the TypeScript interface. Preview audio is requested from Deezer only when played; it is not a training signal. Exporter · Release config · Deployment

Shared listeners can connect different sounds, and dense clusters are not necessarily recognized genres. Source coverage and a two-dimensional projection both lose information.

03

Data sources

Inputs and what we use them for
Source Role Terms / limits
ListenBrainz Per-user artist counts build the listening graph and listening vectors. CC0. The audience is not representative of all listeners.
MusicBrainz Artist IDs, names, external links, and areas connect the datasets. Core data: CC0. User tags have different terms and are not used for release naming.
Discogs Release styles name clusters and rerank similar artists. CC0 dump fields. Coverage depends on available releases and artist links.
Wikidata Genre labels, aliases, artist genres, and geography enrich names. Held-back artist genres also supply a test. CC0. Some genre concepts link to Every Noise, so this is not wholly independent.
AcousticBrainz Recording-level audio descriptors are averaged by artist for layout features. CC0. Incomplete coverage; missing audio-axis values use listening neighbours.
Every Noise at Once Genre names and artist memberships supervise the model. Archived coordinates score maps and previously guided fitting and model selection. Third-party archived snapshots; no open-data license established. Not CC0.

Deezer supplies on-demand interface previews, not training data for this catalog. Extra Last.fm listening datasets and Discogs-EffNet preview embeddings were tested separately and are not inputs to this layout.

Exact snapshots, hashes, and recorded terms: source manifest. Open-source code does not make every input or derived dataset openly licensed.

04

Evaluation

These are held-out experiments, not measurements of the fully refitted production catalog. Exact definitions and runs are linked in the experiment ledger below.

Can the graph recover genres it was not shown?

For evaluation, we hide one fifth of eligible Every Noise genres, including all their training memberships. The listening-graph model finds a matching cluster for 210 of 868 hidden genres. “Matching” means the shared artists are at least 20% of the combined set; it does not mean an exact membership or name match.

These are graph-recovery baselines, not scores for every feature of the final website. Most hidden Every Noise genres are not recovered by this test. The same hidden-name benchmark was used to select a naming variant, so it is not an untouched final test for naming. The production export refits on all eligible labels, including evaluation genres; the shipped catalog is not the held-out test.

Newer music

We tested release 798d8cc1645b on 11,191 artists whose first recorded MusicBrainz release group is from 2024 or later, excluding artists found in the Every Noise crosswalk. The older comparison group has a recorded release before December 2023.

Wikidata genres cover only 3.7% of these newer artists, so the test also uses MusicBrainz tags for scoring only. The table shows the tag-based scores, averaging each artist’s share of labelled top-ten neighbours that share a tag.

MusicBrainz tag agreement among labelled neighbours
Neighbours Newer artists Older artists Random artists
Similar artists 51% 57% 3–5%
Map neighbours 29% 34% 3–5%

Scorable newer artists: 1,596 for similar artists; 1,696 for map neighbours. The rest lack reference tags or labelled neighbours and do not contribute to these scores.

Newer artists score below older artists, but above random. This tests recent-artist placement, not future releases or an independently learned taxonomy. MusicBrainz dates and the Every Noise crosswalk can be incomplete. Test code and recorded results.

06

Every Noise dependence

An independent code and artifact audit found computed geometry, but not an independent taxonomy or model-selection process. These findings refer to the audited release; later name cleanup does not change the training history.

  • We use Every Noise training data. Names and artist memberships supervised 4,344 genres in the audited release—not only names missing elsewhere. Training code · Audited release
  • Today’s positions are calculated, not copied. UMAP fits listening-and-audio vectors; AcousticBrainz features orient the Map. Current fit
  • Coordinate scores influenced the input choice. The listening/audio mix was selected by comparison with Every Noise’s map, and remains in use. Original selection
  • Earlier builds fitted Every Noise coordinates directly. That model was removed; this did not erase the earlier input-selection decision. Replacement
  • The tests have limits. Production refits on all eligible labels, and held-back Wikidata labels do not guarantee source independence. All-label refit · Reference filtering

The audit did not refit the full model or establish rights to derived data.

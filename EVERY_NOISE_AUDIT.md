# OpenNoise and Every Noise at Once: independent audit

**Verdict: issues. The live geometry is not a copy, but it does not meet a strict “coordinates never influenced the release” rule.** The current fit does not use Every Noise x/y as targets or for orientation. It still uses the listening/audio representation that PR #121 made the default on the strength of Every Noise coordinate scores. The project also uses Every Noise artist memberships in production well beyond genres found nowhere else. Earlier builds did train directly on Every Noise positions; v1 had a separate local bootstrap that displayed source positions and colors.

Scope: `h0rv/opennoise` main `45d7c20`, GitHub Pages release `be8d557eda65`, its build lineage, and `archive/v1` at `0a7d77c`. “Every Noise” below means Every Noise at Once (everynoise.com); the inputs are pinned third-party snapshots, not a fresh scrape.

## What actually ships

[Pages run 44436829139](https://github.com/h0rv/opennoise/actions/runs/44436829139) succeeded from `565419e` and logged `CATALOG_RELEASE: be8d557eda65`. The workflow downloads the prebuilt release, builds the web bundle and packs the catalog; it does not run the model. The [live manifest](https://opennoise.horv.co/catalog/manifest.json) matches the [GitHub release](https://github.com/h0rv/opennoise/releases/tag/be8d557eda65); every public genre-index row matches the release archive after the packer's four-decimal rounding. The asset SHA-256 matched GitHub metadata: `665c5924b5d1d2333d424dffcd887a936e9c94049f672d6d7cb78f6d91fad364`.

The shipped chain is **layout fit `cb79969fe147` → placement `76cd232af6e3` → export `3d18e90bfccf` → export `be8d557eda65` → Pages**. The placement ledger hashes the fitted model, input artist vectors, feature file and layout config; local `configs/layout.toml` matches the recorded hash. Both exports record the same placement artifacts; the later export adds related genres. The release producer is the branch cited in the release notes, merged in #155, not the incidental commit pointed to by the asset tag. The shipped export is a variant of `configs/one-name.toml` (see ledger inputs; checked-in config still points to older placement `cdd46331af0a`). The release used a local alias vocabulary path; the exact full producer TOMLs and saved fit inputs were not in the GitHub tarball. Evidence: `experiments/results.tsv:1588,1680–1686`; `configs/one-name.toml:1–15`; `configs/m2e-layout.toml:1–4`; `src/opennoise/placement.py:26–55,139–159`; `src/opennoise/catalog.py:280–300,332–337,378–395`.

The open rebuild in plain terms: ListenBrainz listens give co-listening vectors (ALS) and a separate TF-IDF artist graph. MusicBrainz resolves artist identities, provides areas, and bridges Spotify IDs to MusicBrainz IDs. Discogs styles and Wikidata genre statements name listening clusters, alongside the Every Noise labels and membership seeds. Microgenre candidates combine place and style evidence and use listening neighbors to rank artists. AcousticBrainz recording features are aggregated per artist and combined with listening vectors. UMAP places genre and artist vectors, with the sonic map rotated to fixed audio-feature axes and rank-scaled. That layout is a new calculation; neither its inherited choice of input representation nor the genre catalog is Every Noise-independent.

## Artifact and data checks

Downloaded and verified the current GitHub asset, [quint snapshot](https://github.com/quint-t/Every-Noise-at-Once/blob/e80265defc743b307586ac0a7a5c72d2dacdf409/index.html), NeroYuki @88bd6f6 and the 2021 Watch coordinate CSV against their published SHA-256. Compared the released coordinates to both snapshots by exact genre name among top-level genres; repeated the comparison by supervised source ID (not just display label). Raw coordinate pairs never match; more usefully, even allowing an affine transformation the fits leave substantial variance unexplained, and nearest neighbors largely differ. The 2021 and final reference maps themselves have 16.58% top-10 overlap on 5,380 names in common. The statistics corroborate the non-copy finding; they cannot prove zero data dependence.

See `archive/v1:data/examples/open-genre-taxonomy/{README.md,projection.json}`; the projection has 994 unique English labels and declares no historical inputs. This tests name availability, not Wikidata statement provenance or artist coverage. Names absent from this sample are not necessarily ENAO-exclusive.
- The naming ledger reports **103,146** mapped seeds covering **61,965** artists, and the current export reports **1,333,224** supervised output memberships. Those counts reflect inputs and propagated outputs, respectively. Score-one is not a provenance test: `catalog.py:118–141` compares to the cached model, counts only score-one matches, and hardcodes zero for “unexplained_training_rows.” That does not measure how many published model edges coincide with ENAO pairs at any score. The mapped crosswalk/seed table was not present in the release; no direct pair-overlap count is claimed.

## Evaluation: what “held out” means here

- **M2 evaluation and M3:** The 868 eligible genres are excluded from M2 propagation seeds and M3 outer-limit fitting. For visible M2 genres the artist holdout is a membership-link split per genre, not new artists: the same artist can still be visible in another genre and in the listening graph. M2 evaluation uses hidden membership sizes to set recall cutoffs (`genres.py:99–104`). M3 tunes on a fifth of the visible genres; its outer assessment still allows artists with evidence in related training genres. The all-label catalog export includes the held-out classes by design, so these scores are not evidence that the public release predicts those classes without ENAO.
- **Map evaluation:** Sonic UMAP fits only on training genres, but the held-out test points are constructed using those genres' known ENAO member lists. Also, those points contribute to the pooled rank scale of the audio orientation targets (`layout.py:105–111`). Islands fits its entire roster before scoring. Call these map-agreement diagnostics, not independent discovery or a blind layout test.
- **Wikidata:** `sealed` is SHA-256(MBID) mod 10 = 0 (`metrics.py:8–9`). Those artists' direct Wikidata P136 links are filtered during naming and microgenre fitting (`wikidata.py:70–90,148–175`; `micro.py:154–168`), but those artists can remain in listening, Discogs, audio and ENAO seeds. The evaluation excludes statements with recognized Every Noise URL/stated-in references; “independent” also excludes QIDs with P9881. Neither removes uncited imports, shared named genres, aliases, or influence through other artists' Wikidata rows (training uses direct `wdt:P136` without statement-level provenance). The separate `artists_absent_enao` measure filters against the MusicBrainz/Spotify crosswalk, not the observed membership set, and isn't intersected with the sealed-independent slice. Related-genre ledger scores (.482 all, .574 sealed-independent) compare evaluable pairs only with random baselines; only 439 of 571 eligible sealed-independent source genres got scores. They are not full-coverage guarantees.

## Evidence threshold and next decisions

| 20 | 21,890 (57.9%) | 1,707 |
| 50 | 30,181 (79.8%) | 2,669 |

Current minimum is 3; median is 16 overall and 151 at root. Supervised ENAO rows have at least 35 *predicted* members (median 297); this says nothing about the count of independently confirmed members. A practical candidate: show fewer-than-10-member children in browse/search but not on the default map; for any genre, require direct independent support or consistent placement across resamples before presenting it as high confidence. Measure the loss of geographic/microgenre coverage and artist usefulness separately from counts. Add an “insufficient evidence” state rather than padding memberships from weak signal.

1. **Break the inherited coordinate dependency.** Re-select listening/audio features, weights and models with ENAO coordinate files physically unavailable, using listening holdout and genuinely independent musical evidence. Freeze the choice, compare map quality and support, and compute ENAO agreement only after the frozen release. Add a reproducible test that removing or permuting ENAO coordinate columns and reference colors cannot change any production output, including settings and captions.
2. **Make the seed rule enforceable.** Compare normalized names and aliases against pinned independent vocabularies, label genuinely ENAO-only seeds, and document whether memberships are allowed for them. Run no-ENAO and rare-seeds-only comparisons for coverage, recovery and placement stability. Persist source and evidence counts per label and membership. “Local reference only” is the declaration in `sources.toml`, not permission to redistribute derived artist edges; separate that rights review from this audit.
3. **Separate tuning from testing.** Freeze a final holdout not consulted for naming, thresholds or captions; group near-duplicate genres and report a new-artist/cold-genre slice. Fit sonic rank scales on train only and use an out-of-sample islands transform for test. For independent validation, use curated provenance or a separately sourced panel; disclose the retained coverage and how unknown pairs are treated.
4. **Make the release reproducible.** Publish exact producer configs and an input/decision manifest beside the release (not raw restricted references). Build and attest one release whose fit and model selection cannot read coordinate data. The `map.parquet` name-only readers in `genres.py:16–24`, `layout.py:23–28` and `micro.py:520–550` can use a separate vocabulary artifact.

**About page wording supported now:** “OpenNoise computes new positions from listening and audio measurements. It uses Every Noise genre names and artist-to-genre labels as inputs as well as benchmarks. Earlier experiments trained on Every Noise positions; the live map no longer does, but it still uses a representation originally selected by comparing maps with Every Noise.” Do not say “Every Noise only seeds genres unavailable elsewhere,” “the map has never learned from Every Noise coordinates,” or “sealed Wikidata proves independence.”

**Limits.** No full corpus refit, private experiment replay, exact exclusive-name count, artist-pair copyright/rights determination, pixel-by-pixel code/assets comparison, historical Cloudflare payload replay, or UI visual check. Current HTTP payload, asset inventory and public source flow were checked; no source files changed. Older release contents are traced via code, artifact hashes/ledger and release notes rather than by replaying all archives.
